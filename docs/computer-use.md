# Computer Use

**Our exclusive feature - not part of the official Linux beta.** Claude Desktop's built-in Computer Use MCP server exposes 27 tools for desktop automation (screenshot, click, type, scroll, drag, clipboard, and more). The **learn tools** (`learn_application`, `learn_screen_region`) generate interactive overlay tutorials that walk through any application's UI step by step.

Example prompt: *"Can you use computer use MCP to explain me the PhpStorm application?"*

**How it works on Linux:** upstream Computer Use is macOS-only - gated behind `process.platform==="darwin"`, macOS TCC permissions, and a native Swift executor. The patch ([`fix_computer_use_linux.nim`](../patches/linux/fix_computer_use_linux.nim)) removes the platform gates, routes both upstream executor factories to an injected Linux executor, bypasses TCC with a no-op `{granted: true}`, and auto-detects your session type to route to a bundled first-party bridge: [`x11-bridge`](https://github.com/patrickjaja/x11-bridge) on X11 / XWayland, [`wlroots-bridge`](https://github.com/patrickjaja/wlroots-bridge) on Sway / Hyprland / Niri, [`gnome-portal-bridge`](https://github.com/patrickjaja/gnome-bridge) on GNOME Wayland, and [`kwin-portal-bridge`](https://github.com/patrickjaja/kwin-portal-bridge) on KDE Wayland. The bridges ship inside the package, so X11, XWayland, Sway / Hyprland / Niri, GNOME Wayland on PipeWire >= 1.0.5 (Ubuntu 24.04+, Fedora 40+, Debian 13+) and KDE Plasma 6.6+ need nothing installed. Older GNOME and KDE sessions, NixOS GNOME / KDE and exotic compositors take a fallback; [Computer Use dependencies](computer-use-dependencies.md) has the matrix, how each bridge works and the fallbacks. The app also reports Computer Use to claude.ai as rolled out on Linux ([`enable_local_agent_mode.nim`](../patches/linux/enable_local_agent_mode.nim) forces the `computerUseRollout` feature), so Team and Enterprise accounts without a web rollout get the **Settings -> System -> Computer use** section with its **Enable computer use** switch instead of "Computer use isn't available on the Team and Enterprise plans yet". Turn that switch on once; Code sessions on this computer and Cowork tasks then carry the `computer-use` tools (claude.ai lists Computer Use for those two session kinds; a plain chat reaches a computer only through claude.ai's own device linking). Organization compliance settings are honoured as on macOS and Windows: when your org restricts Computer Use, the server is not registered and, if the restriction lands mid-session, every further tool call is refused with the same message upstream shows; claude.ai checks that compliance lock before the rollout, so it is not lifted by the override.

**Notes:**
- **Primary monitor only.** Screenshots, clicks, and the teach overlay target the primary display; use `switch_display` to target another for screenshots/clicks (teach overlay stays on primary).
- **App discovery** (listing and opening apps, the teach overlay) reads `.desktop` files from `$XDG_DATA_HOME/applications` and every `$XDG_DATA_DIRS/applications` (which covers NixOS profiles, snap and `/usr/local`), plus the Flatpak export dirs, registering each with multiple name variants for flexible matching.
- **Teach overlay** stays interactive but blocks clicks to apps behind it during a tour (Electron's `setIgnoreMouseEvents` is [broken on X11](https://github.com/electron/electron/issues/16777)).

See [CLAUDE_BUILT_IN_MCP.md](../baseline/CLAUDE_BUILT_IN_MCP.md#17-computer-use) for the full tool reference, and [Computer Use dependencies](computer-use-dependencies.md) for the package matrix, the KDE/GNOME portal behavior notes, `COWORK_SCREENSHOT_CMD`, and `ydotool` v1.0+ setup.

**Debugging:** Computer Use patches emit `[claude-cu] diagnostics:` lines showing the detected session, available/missing tools, and screenshot cascade. Find them in `~/.config/Claude/logs/claude-patches.log` (also printed to stderr on terminal launches) and share that file when reporting Computer Use issues. See also [Debugging](../README.md#debugging).
